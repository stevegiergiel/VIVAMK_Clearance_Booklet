V2.18 - STATE-SAFE GITHUB PAGES DEPLOYMENT

Problem fixed
-------------
The Windows daily monitor correctly rebuilds iframe pages with persistent
monitor_state and cached SOLD OUT images. The previous GitHub Actions workflow
then rebuilt the iframe pages again without --state-file, which could erase
the SOLD OUT presentation immediately after the monitor pushed it.

New architecture
----------------
1. Windows daily monitor is the authoritative iframe builder.
2. It scans twice, updates ACTIVE/SOLD_OUT state, uses known-good cached images,
   and generates the affected site/<sale>/index.html.
3. SYSTEM Git pushes only the affected generated site page.
4. GitHub Actions DOES NOT rebuild the catalogue.
5. GitHub Pages deploys the committed site/ directory verbatim.

Result
------
A SOLD OUT card generated by the 9am monitor can no longer be overwritten by
a stateless GitHub Actions rebuild.

The rule applies across Christmas, Mega Sale, Pets, Personalised and
Winter Warmers.

Manual engine/config changes
----------------------------
A source-code/config-only push no longer regenerates the live iframe by itself.
When an immediate iframe refresh is required, run:
    rebuild_all_iframes_local.bat
then review/stage the generated site pages and push them.

This is intentional: only the Windows environment has the persistent monitor
state and cached SOLD OUT images required for a state-correct rebuild.
